# Generated synthetic frontend fixtures

The 19 active examples use the frozen v1 contract, version 1.0.0. Eighteen are generated by passing explicit synthetic normalized provider inputs through the actual astronomy, evaluator and forecast serializer. The error example exercises the actual HTTP failure path with a synthetic exception and deterministic request ID. They are not provider captures, live forecasts, or scientific validation. Snapshot IDs are content hashes of the synthetic normalized inputs; product names, attribution, model version, timestamp precision and future basis come from the implementation.

From `backend`, regenerate with `uv run --offline --frozen python tools/generate_api_examples.py`. Backend tests assert exact recomputation, full schema validity and temporal/provenance invariants.

Future segments carry planning basis only where fresh global Kp context covers their representative sample, while local activity remains unknown/not-covered. Confidence never exceeds low in this prototype. Promising/limited examples are synthetic software scenarios, not observations or live notification validation.

The former manually authored `darkness-unavailable.json` is preserved under `api/legacy-examples` and excluded from active mocks: the implemented pipeline returns 503 on an astronomy failure, rather than the former unimplemented partial-astronomy 200 shape. Backend-owned fixtures preserve the conservative model's uncertainty: a weak overhead signal is unknown local activity, not a supported low-activity result.

Each assessment exposes optional activityEvidence. Qualifying synthetic brackets identify both source instants and a nonzero supportedInterval under retained-bracket-min-v1. upcomingActivityInstant exposes the newest future model point separately. These mocks verify the implemented heuristic; they are not empirical validation.

Every forecast example carries the optional auroraReach, planning[].auroraOutlook and now.activeSince fields ([api.md](../../docs/api.md#what-zorja-forecasts--2026-11-12)). Stockholm samples are edge places, Tromsø and the polar samples are under the zone. In the synthetic samples with an active bracket, activeSince is the earliest synthetic run, so activeSinceIsBufferLimited is true.
