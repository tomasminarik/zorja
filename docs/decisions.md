# Decisions

The single list of decisions currently in force. Product decisions are kept separate from technical choices. A product decision gets a row when it is made; a technical choice gets an entry only when it changes how the app behaves or what it may cost. Later rows may replace earlier ones, and say so.

## Technical choices in force

- **zorja.app (2026-11-12):** a static site in `site/` (plain HTML, CSS and JavaScript, no build step, no third-party scripts, fonts served from the site). The sky is `site/assets/js/sky.js`, a line-for-line WebGL 2 port of `AuroraSkyPhoto.metal` with the app's default parameters, two passes like the app (one pass when float render targets are missing), at most 30 fps and about 2.6 million pixels, paused when the tab is hidden or Reduce Motion is on. The place check's words come from `site/assets/js/forecast-copy.js`, a port of the app's `ScreenWords`, tested against every API example in CI (`.github/workflows/site.yml`). Phone screens are simulator screenshots of the Debug build on bundled samples. The hosted API answers CORS for `https://zorja.app` only (`SITE_ORIGINS` in `api/hosted.py`), before the POST-only rule and any Redis work.
- **Forecast admission (2026-11-18):** once an instance sees the shared per-minute limit reached, it refuses further forecasts for the rest of that minute itself, without a Redis call, so a flood of refused requests costs no allowance. The shared limit is 60 forecasts a minute. The hosted service no longer serves `/docs`, `/redoc`, `/openapi.json`, `/metrics` or `/health/providers`; the local server still does. The collector accepts QStash tokens whose `iat`/`nbf` are up to 60 seconds in the future, for clock drift; expiry is not extended.
- **Backend:** Python 3.13 and FastAPI. Local development uses a SQLite cache; the hosted service uses Upstash Redis.
- **Forecast contract:** `/v1/forecast`, version 1.0.0, frozen in [api/frozen/v1-openapi.json](../api/frozen/v1-openapi.json). New optional fields are allowed. Removing or changing the meaning of a field needs a new major version.
- **Aurora reach (2026-11-12):** corrected magnetic latitude comes from a 1° AACGM-v2 table (110 km, epoch 2026-11-01) stored as a generated Python module, so the hosted bundle (Python files only) carries it and the backend gains no dependency; `backend/tools/generate_aacgm_table.py` regenerates it with `aacgmv2` in a throwaway environment. The southern night outlook uses only the remaining dark hours and is `not_expected` for places the rule never reaches even without Kp data. `now.activeSince` is reported only when the current bracket itself is active. The app trusts the API's night outlook for storm nights and falls back to the Kp bins only for responses without it.
- **Weather expiry grace (2026-11-12):** after a successful MET check, weather stays `fresh` for 3 minutes past its HTTP expiry, or past the check itself when MET's `Expires` had already passed on arrival. 3 minutes is the longest the next scheduled check can take (60 s minimum plus up to 120 s jitter). Before this, every place's weather read `stale` (and the app "Out of date") for up to 2 minutes each MET cycle, and immediately when MET answered with a past `Expires` (seen for Tromsø on 2026-11-12). A failed check still goes stale at the HTTP expiry, and the 6-hour issue-age limit is unchanged. A response carrying an older run than the one stored (MET's cache nodes alternated between the 11:32 and 11:35 runs for Tromsø) is no longer a provider error with growing backoff: the newer data stays, the check counts as successful, and the next one follows after the minimum interval plus jitter.
- **Experimental model:** parameters live in `backend/src/aurora_backend/evaluation/model.py` and are reported by model version (see [forecast-model.md](forecast-model.md) and [assessment-rules.md](assessment-rules.md)). There is no percentage chance of seeing aurora.
- **Automatic checks (2026-11-04):** GitHub Actions runs the backend checks on Linux for pull requests that touch the backend, contract or tools, within the free minutes.
- **Hosted storage (2026-11-03, updated 2026-11-04):** plain Redis commands with per-instance memory caching; the aurora grid is stored once by content, in a lossless compact form (about 5 KB instead of 220 KB). Monthly allowances are 360,000 commands and 8 GB for forecasts and 90,000 commands and 0.5 GB for the collector, below Upstash Free's 500,000 commands and 10 GB. Details in [hosting.md](hosting.md). This replaces an earlier Lua-scripted budget ledger.
- **Aurora sky rendering (2026-11-06):** an `MTKView` draws the Figma sky shader in two passes: the curtain terms that depend only on x and time are computed once per pixel column, then each pixel is shaded. It draws the same image as the one-pass Figma port (a test checks this within rounding) at about a third of the GPU time.
- **Aurora sky motion (2026-11-09):** the sky looked still on a phone. Figma has no motion spec for the sky (it is a shader fill without keyframes), so these values are set in code: shader time runs at 1× real time instead of the layers' 0.3×; rays drift sideways along the curtain (0.5 ray-noise units a second, about 15 pt a second on the main curtain); and a brightness pulse about a third of the screen wide travels along the curtains, crossing the screen in about 10 s (depth 0.35). The pulse depends only on x and time, so it is computed in the per-column pass and costs almost nothing per pixel. Both motion terms are zero in `AuroraSkyParameters.figma`, which still matches Figma's still frames. Frame rate (30 fps) and the pause rules (background, Low Power Mode, Reduce Motion) are unchanged. A test checks that frames 4 s apart differ at least three times as much as with Figma's values.
- **Optical centring in pills (2026-11-09):** labels and icons looked off-centre in buttons, tags and the location chip. Figma itself was not the cause: the app matched its components to within half a point. The causes were: (1) the app scaled 24 pt icons down to 16 and 20 pt, thinning the 1.75 stroke to 1.17 and 1.46 pt, while Figma keeps 1.75; `tools/make_icon_sizes.py` now generates 16 and 20 pt variants that keep the stroke, plus a table of each glyph's ink inset (`IconGlyphInsets.swift`); (2) Outfit's font box puts its capitals 0.2–0.3 pt below the middle of the line box, so one-line labels in pills (`textStyle(_:capCentered: true)`) centre the capitals instead; (3) an icon's glyph sits inside its frame, leaving more space on the icon's side than after the label, so buttons and the chip shift their content by half the difference (`glyphInsets` minus Outfit's 0.9 pt side bearing). Sizes stay as in Figma. Measured on the simulator, every button variant, tag and the chip are now centred within 0.2 pt both ways.
- **Screen state (2026-11-06):** one pure function, `ScreenState.make`, picks the Figma state, sky level and words from the forecast and the app's request state. A forecast past `refreshAfter` is never shown as current: online it reads "Out Of Date Since" its `generatedAt`, offline "No Connection.", after a failed request the error screen. Two readings of [App copy](copy.md): `no_darkness_within_horizon` wins over the first blocker, because midnight sun also carries `daylight` and would otherwise read "Too Bright Tonight."; and "Out Of Date Since" / "Last update" use the newest issue time of the stale source the `source_stale` reason points to. A `wait` for daylight or twilight whose next dark window starts after tonight's planning period reads "Too Bright Tonight." with "`<Day>` Gets Dark.", because the backend waits for any window within 72 hours.
- **Text drawing (2026-11-06):** every text style draws through a renderer that may paint past the text's frame, because an exact line height clipped the descenders of Display/XL (60 on 60) on screen, and that centres each line in its line box as Figma does: SwiftUI put the whole difference between Outfit's height and a smaller line height below the line, so Display/XL sat 8 pt and Display/L 4 pt lower than in Figma. Since 2026-11-09 the renderer measures lines from where the layout says the text starts: iOS 27 starts the first line lower than iOS 26 (3 pt for Label/M, 10 pt for Display/XL), and text drew that much too high on an iOS 27 phone. A test renders text and checks where its capitals land.

Exporting registered the explicit App ID `com.tomasminarik.Zorja`; until then automatic signing used the wildcard ID. Uploads must sign with a local Apple Distribution certificate on the Mac: with only the cloud-managed one, Xcode passes the certificate name (the developer's name, which has accented letters) to `codesign`, which stores the accented letters in decomposed Unicode, so the signature fails its own requirement and App Store Connect rejects it (error 90035, "Invalid Signature"). The first build, 0.1 (1), was uploaded on 2026-11-12 and installed from TestFlight on a test iPhone the same day.
- **Privacy:** location is never in URLs, logs, error messages or Redis key names. Raw provider data is never used after 48 hours; hosted weather entries expire within 6 hours.
- **Pre-release review fixes (2026-11-13):**
  - **Expired forecast.** Past `refreshAfter` with no failed request (the next check is running or due), the app still withdraws the guidance. It now says "Zorja is getting fresh data. Don’t rely on the last forecast until it arrives." instead of "can’t get fresh data", and it hides "Checking Again At" while the request runs.
  - **My Location.** It is read again when the app returns to the foreground and the last reading is over 30 minutes old.
  - **Time zone fallback.** A place MapKit gives no time zone for (pinned offline, at sea) keeps the phone's zone only when that zone is within 2 hours of the place's solar time; otherwise it gets a fixed `Etc/GMT` zone from its longitude.
  - **Pick On Map.** It waits for a moved pin's name before it can be used.
  - **Hosted refreshes.** A request that finds another instance refreshing a source waits up to about 1 second, then judges the stored data on its own dates, not as a failed refresh. A refresh cancelled by the deadline releases its lease in the background.
  - **Hosted precision.** Providers and the shared cache see coordinates rounded to two decimals.
  - **Release build.** Release builds no longer bundle the sample forecasts.
  - **Request limits per place.** `ForecastLoader` keeps a forecast, problem and next start per place for the session (in memory only). A place's next start is `max(start + 60 s, refreshAfter)`; any two starts are at least 5 s apart; a Retry-After holds back every place; a cancelled request leaves only the 5 s. One device can now start up to 12 requests a minute while switching, against the hosted cap for all users (30 a minute then, 60 since 2026-11-18).
